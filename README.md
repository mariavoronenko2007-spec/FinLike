## FinLake

FinLake — AI-ассистент для безопасной работы с данными университета на естественном языке.

Пользователь задаёт вопрос в чате, YandexGPT преобразует его в SQL, запрос проходит проверку безопасности и выполняется в PostgreSQL. Пользователь получает понятный ответ, сформированный SQL и результат в виде таблицы.

Проект разработан в рамках хакатона **«Код Байкала 2026»**.

## Как работает FinLake

```text
Пользователь
    ↓
Frontend
    ↓
FastAPI
    ↓
YandexGPT
    ↓
SQL
    ↓
Проверка безопасности
    ↓
PostgreSQL
    ↓
Ответ + SQL + таблица
```

YandexGPT не имеет прямого доступа к базе данных. Модель получает вопрос пользователя и актуальную схему PostgreSQL и формирует SQL. Перед выполнением запрос обязательно проверяется приложением.

## Основные возможности

- вопросы к базе данных на естественном языке;
- генерация SQL с помощью YandexGPT;
- автоматическое получение схемы PostgreSQL и связей между таблицами;
- работа с `JOIN`, фильтрацией, сортировкой и агрегатными функциями;
- проверка SQL перед выполнением;
- отображение SQL пользователю;
- вывод результатов в виде таблицы;
- разграничение доступа по ролям;
- защита персональных данных;
- авторизация пользователей;
- личные кабинеты;
- работа без авторизации с ограниченным доступом;
- создание и сохранение диалогов;
- история сообщений;
- индикатор загрузки;
- обработка некорректных запросов и ошибок.

## Роли пользователей

Система определяет роль по логину пользователя:

| Роль | Формат логина |
|---|---|
| Студент | `STU-XXXX` |
| Преподаватель | `TEA-XXXX` |
| Абитуриент | `APP-XXXX` |
| Администрация | `ADM-XXXX` |

Права доступа зависят от роли.

Студент может работать со своими данными, но не получает персональные данные других студентов и абитуриентов.

Абитуриент может получать информацию о собственных заявлениях и поступлении.

Преподавателю доступна информация, необходимая для учебной работы.

Администрации доступна расширенная информация и статистика университета.

Без авторизации FinLake предоставляет только разрешённую общую, агрегированную или обезличенную информацию.

## Безопасность

Перед выполнением SQL проходит проверку в `security.py`.

Реализованы:

- только `SELECT`-запросы;
- запрет выполнения нескольких SQL-запросов одновременно;
- блокировка изменяющих команд;
- whitelist разрешённых таблиц;
- автоматическое добавление `LIMIT`;
- `statement_timeout = 5000 ms`;
- проверка прав пользователя;
- защита персональных данных студентов и абитуриентов;
- блокировка запросов паролей, API-ключей, токенов и `.env`.

Запрещены команды:

```text
INSERT
UPDATE
DELETE
DROP
ALTER
CREATE
TRUNCATE
```

SQL выполняется в PostgreSQL только после успешного прохождения проверки.

## База данных

Проект использует PostgreSQL.

Файл `database.sql` содержит структуру базы и тестовые данные проекта.

Используются таблицы:

| Таблица | Назначение |
|---|---|
| `faculties` | факультеты |
| `programs` | образовательные программы |
| `students` | студенты |
| `teachers` | преподаватели |
| `courses` | дисциплины |
| `grades` | оценки |
| `schedule` | расписание |
| `applicants` | абитуриенты |
| `applications` | заявления на поступление |
| `administration` | сотрудники администрации |
| `chats` | диалоги пользователей |
| `chat_messages` | сообщения в диалогах |

Основные связи:

```text
faculties
├── programs
│   ├── students ── grades
│   └── applications ── applicants
├── teachers ── courses
│                ├── grades
│                └── schedule
└── administration

chats ── chat_messages
```

В тестовой базе находятся факультеты, образовательные программы, студенты, преподаватели, дисциплины, оценки, абитуриенты, заявления и сотрудники администрации.

## История и журналирование взаимодействий

Для авторизованных пользователей FinLake сохраняет историю работы с ассистентом в PostgreSQL.

Таблица `chats` хранит информацию о диалогах, а `chat_messages` — сообщения пользователя и FinLake вместе со временем их создания.

Это позволяет сохранять пользовательские взаимодействия и открывать предыдущие диалоги из интерфейса.

## Тестирование

Работа FinLake проверялась на контрольном наборе вопросов к базе данных.

В ходе проверки тестировались:

- генерация корректного SQL;
- запросы с `JOIN`;
- агрегатные запросы;
- соответствие результатов данным PostgreSQL;
- вопросы для разных ролей пользователей;
- защита персональных данных;
- блокировка запрещённых запросов;
- обработка некорректных вопросов и ошибок.

## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd FinLake
```

### 2. Создать виртуальное окружение

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Подготовить PostgreSQL

Создайте базу данных PostgreSQL и выполните:

```text
database.sql
```

SQL-файл создаст необходимые таблицы и добавит тестовые данные проекта.

### 5. Настроить переменные окружения

Создайте `.env` на основе `.env.example`:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=university
DB_USER=postgres
DB_PASSWORD=your_password

YANDEX_API_KEY=your_yandex_api_key
YANDEX_FOLDER_ID=your_yandex_folder_id
```

Настоящий `.env` содержит секретные данные и не должен добавляться в GitHub.

### 6. Запустить backend

```bash
uvicorn api:app --reload
```

API будет доступно по адресу:

```text
http://127.0.0.1:8000
```

Документация FastAPI:

```text
http://127.0.0.1:8000/docs
```

### 7. Запустить frontend

Запустите локальный web-сервер для папки `frontend` и откройте:

```text
frontend/home.html
```

Во время работы должны быть доступны PostgreSQL, backend FinLake и YandexGPT API.

## Пример работы

Пользователь задаёт вопрос:

```text
Сколько студентов обучается на программе «Программная инженерия»?
```

YandexGPT формирует SQL, используя схему базы данных:

```sql
SELECT COUNT(*)
FROM students s
JOIN programs p ON s.program_id = p.id
WHERE p.name ILIKE '%Программная инженерия%';
```

Запрос проходит проверку безопасности, после чего выполняется в PostgreSQL.

Результат возвращается в интерфейс вместе с SQL-запросом.
